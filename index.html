NEW HERE? START WITH THESE THREE STEPS

How to use the toolkit.

You do not need an account or special setup. Choose a checker, try a sample, and read the results.

  1. 1

    Choose a tool

    Use the HTML accessibility checker for markup, or the subtitle validator for SRT and WebVTT files.

  2. 2

    Try an example first

    Select “Load example” if you are exploring. Otherwise paste HTML or subtitle text, or choose a subtitle file.

  3. 3

    Run the check and review

    Read the findings and suggestions. Results highlight selected issues; they do not certify that content is accessible.

Privacy: this demo processes your input in your browser. Do not use public demos with confidential or personal information.

HOW TO READ THE RESULTS

A useful signal.
Not the whole story.

Automated checks can reveal patterns and potential defects, but accessibility depends on context and real user experience. Treat every result as a prompt for review, not a final verdict.

Error

A likely issue that should be investigated and corrected.

Warning

A possible usability or quality concern that needs context.

Info

A useful statistic or observation, not necessarily a defect.

!

Know the limitations

This is an early browser-based demonstration. Its JavaScript checks are a separate, lightweight implementation; they do not execute the repository's PHP command-line auditor or a production Java subtitle engine. It does not calculate full WCAG conformance, inspect rendered colour contrast, or replace keyboard, screen-reader and user testing. Do not use the output as a legal compliance certificate.

PROJECT INFORMATION

About the project.

Who created this toolkit, why it exists, and how you can use or build on it.

01

Creator & origin

The original idea, project concept and direction are by Marika Matalamäki. This is an independent portfolio and learning project developed to bring web accessibility checks and subtitle quality assurance together.

02

Why it was made

The goal is to make selected technical checks easier to explore, explain common quality issues, and encourage inclusive digital services. Accessibility is broader than automated rules: real users, context and manual evaluation matter.

03

How to use it

Choose an HTML or subtitle tool, paste sample content or select an SRT/VTT file, and review the report. Browser-demo inputs are processed locally and are not uploaded. Do not enter confidential or personal data into a public demo.

04

Contributions

Open repository and contribution options ↗
06

Current scope

The published browser version is an early demonstration with selected JavaScript checks. The PHP command-line auditor is a separate module; the Java subtitle engine and database are planned work. This demo is not a complete WCAG audit or certification.
